# SAP ERP 저널엔트리 이상거래 탐지 및 감사 설명 자동화

비지도학습 기반 이상거래탐지(Autoencoder)에 생성형 AI API와 RAG(검색증강생성)를 결합해,
탐지된 이상거래에 대해 감사기준서 근거를 곁들인 자연어 설명을 자동 생성하는 프로젝트입니다.

## 프로젝트 개요

- **v1 (캡스톤 디자인)**: SAP ERP 저널엔트리(약 33만 건)를 대상으로 Autoencoder 기반
  비지도학습 이상탐지 모델을 구축. 상위 1%(v99) 임계값 기준 851건의 전표(3,322개 라인)를
  이상 의심 거래로 탐지하고, 룰 기반 로직으로 1차 설명·리스크 스코어링을 수행.
- **v2 (RAG 확장)**: v1의 룰 기반 탐지 결과 위에, 생성형 AI API(GPT)와 RAG를 결합한
  설명 계층을 추가. 감사기준서(240·315·330·1100) 원문에서 관련 조항을 검색해 근거로 제시하고,
  감사인이 바로 읽을 수 있는 자연어 설명·후속 절차를 생성.

v1과 v2는 별개 산출물이며, v1의 탐지 결과(CSV)는 그대로 유지한 채 v2가 그 위에
설명 레이어를 얹는 구조입니다. (자세한 내용은 아래 "설계 배경" 참고)

## 아키텍처

```
[SAP ERP 데이터 33만 건]
        │  (v1) 21개 피처 엔지니어링
        ▼
[Autoencoder 비지도학습 이상탐지]
        │  v99 임계값(상위 1%)
        ▼
[851건 이상 전표 + 룰 기반 1차 설명/리스크 스코어]  ← ae_detected_doc_summary_v99.csv
        │
        │  (v2) 탐지 유형 분류 → 감사 실무 용어로 변환
        ▼
[TF-IDF 검색: 감사기준서 240/315/330/1100 원문 (294개 문단)]
        │  관련 조항 top-3 검색 (또는 fallback 시 검색 생략)
        ▼
[GPT API: 전표 데이터 + 검색된 조항 → 구조화된 감사 설명 생성]
        │
        ▼
[audit_explanations_v99.json]
```

## 설계 배경 (왜 이렇게 만들었나)

- **비지도학습을 쓴 이유**: 회계부정/이상거래는 라벨링된 데이터가 거의 없어, Autoencoder 기반
  이상탐지가 실무에서도 표준적으로 쓰이는 접근입니다.
- **RAG를 추가한 이유**: LLM이 근거 없이 그럴듯한 설명을 만들어내는 환각(hallucination) 위험을
  줄이기 위해, 실제 감사기준서 원문(한국공인회계사회 발간 2025년 11월 개정판)에서 관련 조항을
  검색해 근거로 제시하도록 설계했습니다.
- **탐지 유형 → 감사 용어 매핑**: 룰 기반 탐지 사유는 통계 용어(z-score, 반올림 등)로 쓰여 있어
  기준서 원문(감사 실무 용어)과 어휘가 겹치지 않는 문제가 있었습니다. 이를 해결하기 위해
  탐지 유형별로 감사 실무 용어 쿼리로 변환하는 매핑 테이블을 추가했습니다.
- **fallback 처리**: 851건 중 약 40%(343건)는 단일 룰이 아니라 Autoencoder의 종합 재구성오차로만
  탐지된 경우입니다. 이 경우 특정 기준서 조항을 억지로 연결하지 않고, "근거 조항 없음"을
  명시적으로 출력하도록 설계했습니다.
- **2단계 검증**: 검색(TF-IDF)은 어휘 기반이라 정확도에 한계가 있어, LLM이 검색된 후보 조항의
  실제 관련성을 다시 판단하고 관련 없으면 "관련성 없음"이라 쓰도록 시스템 프롬프트에 명시했습니다.

## 한계 (정직하게 밝힘)

- 검색은 임베딩 기반 의미 검색이 아니라 TF-IDF(char n-gram) 기반이라, 관련 조항을
  항상 정확하게 찾아준다고 보장할 수 없습니다. 이를 보완하기 위해 LLM이 관련성을
  한 번 더 검토하도록 설계했으나, 완전한 해결책은 아닙니다.
- 이 프로젝트는 실제 감사 의견을 대체하지 않으며, 어디까지나 감사인의 1차 검토를
  돕는 보조 도구로 설계되었습니다.
- 표본 규모(고위험 12건)로 우선 검증했으며, 전체 851건에 대한 전수 실행 및 검증은
  추가 진행 중입니다.

## 실행 방법

```bash
pip install -r requirements.txt
cp .env.example .env  # 발급받은 OPENAI_API_KEY 입력

# 1) 감사기준서 원문 PDF에서 관련 조항 추출 (최초 1회)
python src/extract_audit_standards.py

# 2) RAG 기반 감사 설명 생성
python src/rag_audit_explainer.py
```

## 폴더 구조

```
├── src/
│   ├── extract_audit_standards.py   # 기준서 PDF → 근거 코퍼스 생성
│   └── rag_audit_explainer.py       # TF-IDF 검색 + GPT API 호출 파이프라인
├── standards_corpus/                 # 감사기준서 240/315/330/1100 발췌 (294개 문단)
├── data/
│   └── ae_detected_doc_summary_v99.csv  # v1 탐지 결과 (문서 단위, 851건)
├── outputs/
│   └── audit_explanations_v99.json  # v2 생성 결과 샘플 (고위험 12건)
├── requirements.txt
└── .env.example
```

## 기술 스택

Python, pandas, scikit-learn(TF-IDF), OpenAI API(GPT-4o-mini), pypdf
